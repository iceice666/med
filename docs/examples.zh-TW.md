# 範例程式

## 範例面板

沒有初始化檔的編輯器就只是編輯器本身，連按鍵都沒有。檔案樹、搜尋器、git 畫面與接下來可按按鍵的清單，都是 [`examples/`](../examples) 裡的程式，由初始化檔載入它想要的部分：

```lisp
; ~/.config/med/init.lisp
(load "/path/to/med/examples/init.lisp")   ; 全部載入（包括按鍵），或逐一載入：
(load "/path/to/med/examples/vim.lisp")
(load "/path/to/med/examples/keys.lisp")
(load "/path/to/med/examples/tree.lisp")
```

不是從根目錄開始的路徑，會在載入它的檔案旁邊尋找，所以也可以把這些檔案複製到 `init.lisp` 旁邊再修改。每個檔案都帶有自己的命令與按鍵：

| 檔案 | 按鍵 | 動作 |
| --- | --- | --- |
| `vim.lisp` | | 各模式的 vim 按鍵：見[按鍵](keys.zh-TW.md#按鍵) |
| `keys.lisp` | | 語言伺服器、分頁、flash 的按鍵，`space` leader 鍵與 `⌘` 快捷鍵 |
| `tree.lisp` | `space e` / `⌘⇧E` | 開啟並聚焦檔案樹，在檔案樹中再按一次則收起（`j k h l`、`enter`、`R` 重新整理、`q` 收起） |
| | `⌘B` | 顯示 / 隱藏檔案樹（啟動時隱藏） |
| `picker.lisp` | `space f` / `⌘P` | 尋找檔案 |
| | `space /` / `⌘⇧F` | 在專案中搜尋 |
| `git.lisp` | `space g` / `⌘⇧G` | git 畫面 |
| `which-key.lisp` | | 停頓片刻後，列出接下來可按的鍵 |
| | `?` | 在檔案樹或 dired 清單中：立即列出它的所有按鍵（由 `init.lisp` 設定） |
| `todo.lisp` | `]T` / `[T` | 在含有 TODO、FIXME 或 NOTE 的行旁加上標示，並在它們之間跳轉 |
| `dired.lisp` | `space -` | 檔案所在的目錄，如同 Emacs 的 dired |
| | `enter` / `-` | 在清單中：開啟該行的檔案或目錄 / 往上一層 |
| | `i` | 在清單中：編輯名稱，如同 wdired |
| `statusline.lisp` | | 以可修改版面呈現的狀態列：就是沒有它時視窗所畫的那一個 |
| `titlebar.lisp` | | 標題列：正在編輯的內容、專案及其分支 |
| | 點擊分支 | 切換分支（也可用 `:titlebar.branches`） |

有了 `which-key.lisp`，輸入到一半的命令（`g`、`space`、`d g`）在 300 毫秒（`which-key-delay`）內沒有新輸入時，會在視窗底部列出接下來可以按的鍵，在編輯器和面板中都一樣，按 escape 則放棄該命令。只作為較長綁定開頭的按鍵，會顯示以它開頭的綁定數量，或顯示一個名稱：`(which-key-name "<Space>g" "git")`。它會把 `key-timeout` 設為 `nil`：`space` 不會在一秒後自行向右移動，而是等待下一個按鍵。`(which-key-help-key 'tree "?")` 讓 `?` 在某個按鍵表中立即列出其中所有按鍵，接著按下的鍵就照它在那裡的綁定執行；`init.lisp` 在檔案樹與 dired 清單的按鍵都綁好之後替它們這樣設定，因為之後才綁的鍵不會出現在清單上。

有了 `picker.lisp`，`gr` 會列出參照讓你選擇；沒有它時，`gr` 會直接跳到第一個。

有了 `dired.lisp`（如同 Emacs 的 dired），目錄就是一個列出名稱的分頁，每行一個，目錄名稱後面帶 `/`，git 忽略的項目也會列出，每個名稱後面附上 `ls -l` 的資訊。按鍵是 dired 的，放在 `dired` 表中，vim 的移動也照常可用；沒有進入編輯時，清單內容維持顯示時的樣子。`m` 標記檔案，`d` 將它標為待刪除，`u` 與 `U` 取消標記，`t` 反轉標記，`* *`、`* /`、`* @`、`* .`、`% m`、`% d`、`~` 和 `#` 則依種類、副檔名或正規表示式來標記或標為待刪除。對已標記的檔案（沒有標記時則對當行的檔案），`C` 複製，`R` 重新命名或移動，`S` 與 `H` 建立連結，`% C` 與 `% R` 依正規表示式複製與重新命名，`D` 刪除（`x` 刪除標為待刪除的），`M` 與 `O` 更改權限模式與擁有者，`T` 執行 touch，`Z` 壓縮與解壓縮，`!` 執行 shell 命令（命令中單獨的 `*` 代表所有檔案，`?` 代表逐一處理每個檔案），`=` 比較差異；`+` 建立目錄。需要輸入名稱或 y 確認時，會在彈出視窗中詢問。`s` 以最新的優先排序，`(` 隱藏詳細資訊，`g r` 重新讀取磁碟，`q` 關閉清單。設定 `(set! dired-dwim-target true)` 後，如同 Emacs，`C`、`R`、`S` 和 `H` 會預先提供下一個窗格中清單的目錄，讓並排的兩個清單能互相複製與移動；完成後，每個顯示中的清單都會重新讀取磁碟。一個清單只存在於一個窗格中：在新窗格（`ctrl-w v`）中，`space -` 會列出專案根目錄，把清單從原本所在的窗格移過來，`enter` 再從那裡往下進入；回到檔案所在的窗格按 `space -`，則會列出該檔案的目錄。

`i`（或 `C-x C-q`）會進入名稱編輯，如同 wdired。改掉一個名稱後按 `:w`（或 `C-x C-s`）就會重新命名該檔案；名稱中含有 `/` 會移動檔案，必要時會建立目錄。空白行會把該行的檔案移到垃圾桶，這需要 `:w!`。除非全部都能完成，否則什麼都不會做：行數必須和檔案數相同，新名稱也不能是已存在的名稱（包括其他行的名稱），因此兩個檔案互換名稱需要寫入兩次。`C-c C-k` 放棄變更。清單中不會插入子目錄，也不支援在檔案中搜尋或取代。

git 畫面（如同 lazygit）：`1`–`5` 或 `tab` 切換面板，`j`/`k` 移動，`J`/`K` 捲動差異，`space` 暫存 / checkout / 套用，`a` 全部暫存，`c` commit，`A` amend，`d` 捨棄 / 刪除 / drop（會先詢問），`n` 新分支，`s` stash，`g` pop stash，`p` pull，`P` push，`f` fetch，`enter` 開啟檔案，`q` 關閉。
